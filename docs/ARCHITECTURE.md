# Architecture and continuity

Hermès iOS is one SwiftUI application with a Foundation-only core package for tests. The app links the pinned WebRTC M153 binary distributed by stasel/WebRTC for native duplex audio. The Foundation core has no external dependency. Apple frameworks provide rendering, HTTP, WebSocket, secure credential storage and local data protection. The app has no hosted component.

## Ownership

```
SwiftUI views → AppModel → HermesSocket → /api/ws → official Hermes handlers
                   │         │
                   │         └─ HermesHTTP → native auth / short-lived WS ticket
                   └─ LocalCache (display projection, drafts and local reading state)
```

Hermes owns context, memory, skills, tools, model selection and persisted messages. Hermès iOS does not replace Hermes’ model history with a local reconstruction. GPT-Live receives a bounded text projection of the open chat for spoken continuity. A message is `prompt.submit {session_id, text}` on the existing native runtime session.

A saved gateway has a UUID and an endpoint including any proxy prefix. Every cached conversation is scoped by gateway, profile and stored session ID. Runtime IDs are kept separately and rebound by `session.resume`. Selection and connection generations prevent stale async results from taking over a different conversation.

## Fast path

Saved chats and drafts render before the network is contacted. The socket stays open while the app is in the foreground. Native `ping` heartbeats detect a half-open connection. Token events are applied in batches at approximately 30 updates per second; control and completion events flush immediately. Cache writes are throttled to checkpoint ongoing streams every approximately 500 ms and happen on a separate actor; continuous token output cannot postpone the checkpoint indefinitely.

The view keeps stable message identities during hydration and follows the last message only while the reader is near the bottom. A tiny connection indicator reports availability; there is no full-screen sync overlay or forced clearing of chat. The composer remains editable offline.

Chat is the persistent root screen. The header names the conversation and its agent/gateway. The composer is one rounded surface: send/stop sits beside the text, above an integrated control row for attachments, profile switching, chat history, tools and voice. There is no navigation row outside the bubble. The profile shortcut can drop its name at narrow widths while keeping its accessibility label and a 44-point hit target. Send errors appear beside the draft; success confirmations use a dismissible, temporary banner rather than an alert.

The profile picker groups native pins and locally recorded recent visits, shows the gateway and marks observed unread activity. Selecting the active profile leaves its current chat untouched; another profile opens its native canonical Bot Chat in two taps. « Gérer les agents » pushes the agent hub inside the same sheet. Tapping the chat title opens the same picker. The composer's Menu button opens one sheet holding one `NavigationStack` (`MenuView`): the current agent card (pushes its settings), up to three editable favorites stored in local app preferences, « Travail » (conversations, routines, Kanban, workspace, groups), « Mes agents » (profiles of the current server — one tap opens the chat, the slider opens its settings; hidden profiles stay hidden unless « Afficher les agents masqués » is on — plus « Gérer et créer » and the other saved servers) and « App » (connections, notifications, about). A `.searchable` field searches destinations, agent settings pages and the current agent's configuration fields. Every destination is pushed; only focused editors (new routine, new agent, MCP server…) are modal. `AgentSettingsView` groups one profile's pages in « Essentiel » (model, voice, permissions, memory and personality, skills, tools and MCP), « Connexions » (keys, providers, messaging, extensions) and « Avancé » (the remaining catalogue sections and other fields). Screens use native navigation titles and toolbar items, so iOS 26 draws its Liquid Glass bars; `ReturnToChat` in the environment closes the sheet from any depth. While Hermes data has never been loaded (no cache), lists show `SkeletonRows` placeholders, and an uncached conversation shows `SkeletonBubbles`. Opening the menu does not remount the chat.

The design separates stable navigation destinations from message actions, following Apple’s [tab bar guidance](https://developer.apple.com/design/human-interface-guidelines/tab-bars). Native [sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) preserve the underlying conversation while choosing an agent or tool. The composer’s plus menu contains only photo and file attachment pickers. A separate waveform button opens the voice conversation; new chat stays in the header. Visual references for the two-level input layout: [ChatGPT iOS](https://community.openai.com/t/i-need-help-urgently-my-microphone-icon-disppeared/1137756), [Claude iOS](https://www.tomsguide.com/ai/claudes-free-voice-mode-has-landed-heres-how-to-access-it), and [Gemini iOS](https://gigazine.net/news/20241115-gemini-iphone-app/).

Native tools capture connection ID and profile when opened. AppModel checks both before requests and checks the connection generation again after each response. Read results are cached in memory by connection/profile/resource/query and revalidated without clearing existing rows. A load generation prevents a superseded board request from replacing the selected board. Kanban passes an explicit board slug and never changes Hermes’ global current-board pointer; visible boards refresh every eight seconds and stop polling when inactive.

## Automatic voice conversation

`VoiceConversation` starts on opening the voice screen and runs listening → transcription → native agent → speech → listening without push-to-talk or a manual send control. Quiet rooms remain ready; the former 15-second idle pause is removed. Levels are measured on the audio thread per buffer, with each buffer's real duration, and delivered through an `AsyncStream`: no fixed-interval polling on the main actor. End of speech uses an adaptive noise floor (onset at about twice the floor, silence at about 1.5×) and the profile's `voice.silence_duration`, except that Hermes' 3.0 s default becomes 0.8 s; any explicit server value is honored. Speech resumed while the previous utterance is being transcribed is merged into the same request. The native `config.get` response is read transiently for voice settings and is never cached. Whole configured stop phrases end the loop; phrases inside a longer request do not. Spoken turns use the same native prompt path without consuming a written draft or its attachments.

`PhoneAudio` is the MainActor permission/presentation boundary. Its shared `VoiceAudioEngine` owns one duplex `AVAudioEngine` and player node for microphone monitoring and output. It configures `.playAndRecord`/`.voiceChat`, supports Bluetooth HFP and explicitly enables Apple's voice processing on the input node. Graph changes, audio-session work, conversion, WAV encoding and fallback file decoding run on a serial audio worker shared across voice-screen lifetimes. Capture/playback generations prevent a late callback or teardown from taking ownership of a newer call. Audio render taps update bounded PCM storage and meter state; they do not perform disk I/O or enqueue an unbounded task per buffer.

Microphone audio is resampled to 16 kHz mono Int16 on the audio thread (about 100 ms blocks), with a 1 s pre-roll, capped at the profile's `voice.max_recording_seconds` (5–300 s). When the profile enables `stt.streaming`, `StreamingTranscriber` opens authenticated `/api/audio/transcribe-stream` at speech onset and sends PCM while the user speaks; partial text is shown under the title and the final transcript is ready at end of speech. A local 16 kHz WAV is recorded in parallel, so an `error` frame (including the immediate "no live STT" for providers such as Groq), a 6 s stall or a socket failure falls back to `POST /api/audio/transcribe` without losing the utterance; live STT is then disabled for the rest of the call. The client neither invokes the server-microphone `voice.record` RPC nor contacts voice providers directly, and never fetches `/api/audio/voice-config`.

`NativeSpeechStream` opens Hermes' authenticated `/api/audio/speak-stream` as soon as speech ends (while transcription runs), and sends answer text immediately: Hermes 0.21.7 sends `{"type":"start"}` only with the first PCM chunk, so the reader parses `start`, PCM, `end` and `fallback` lazily. Answer deltas arrive by push from `AppModel.speechSink`, straight from the socket before UI batching, and are forwarded in order; the final `message.complete` only appends a strict continuation, then `done`, so a normalized final text never ends the call. Chained turns send `voice_turn: true` so Hermes uses its fast `auxiliary.voice_chat` route. Hermes owns sentence splitting, Markdown cleanup, provider selection and voice; chunked-PCM providers (OpenAI, ElevenLabs) start audio during generation, others speak per sentence. Received mono PCM is split into approximately 200 ms blocks, converted on the audio worker and scheduled through the same duplex graph. A 2 MiB WebSocket frame limit and approximately 3.2 seconds of decoded-audio backpressure bound streaming playback work. If the native endpoint requests fallback or is unavailable, `/api/audio/speak` supplies the regular speech response; its file is decoded in small chunks through the same engine and removed during cleanup. Starting playback does not change to a playback-only audio session or disable microphone monitoring.

Barge-in is active while the agent thinks and while it speaks, following `voice.barge_in`, `voice.barge_in_threshold_multiplier`, `voice.barge_in_grace_seconds` and `voice.stop_phrases`. Thresholds scale with the multiplier (about 500 RMS when quiet, 1000 during playback, capped at 4000) on top of Apple's voice-processing echo cancellation, and an echo guard ignores captured playback. Confirmed speech stops playback, keeps its beginning through the pre-roll, interrupts a still-running native turn and submits the next turn with `interrupted: true`. An interrupt that is not acknowledged is retried once, then reported as a notice while listening continues. Approval, clarification and credential requests put the call in a waiting phase (spoken and written notice) until answered in the chat; transcription, speech and turn errors are notices, not the end of the call. Detection evidence resets on playback onset and mute/unmute. Mute discards capture/pre-roll and suppresses input while allowing output to finish. The two primary controls are microphone mute/resume and end call; there is no manual “send my speech” action.

The voice screen isolates its decorative `Canvas` in a small view with a 24 fps animation clock. Meter updates and the expandable transcript do not invalidate the complete screen. Motion stops while inactive/paused and when Reduce Motion is enabled. Controls remain outside the scrolling content with 68-point icons and wrapping Dynamic Type labels. The conversation state is always also communicated with text.

Dismissal, backgrounding, route failures and system interruptions stop local audio, release the TTS lease and invalidate pending callbacks. The agent may finish an already accepted turn in chat. GPT-Live uses a separate native WebRTC transport, described below. Apple's voice processing is enabled for acoustic echo cancellation, but its effectiveness depends on the route and environment. The simulator fixture covers two automatic turns after an 18-second quiet start with the written draft intact; microphone quality, Bluetooth routing and speaker echo still require physical iPhone testing. See [validation results](VALIDATION.md).

## GPT-Live voice

`VoiceLiveTransport` uses the Google WebRTC implementation packaged by [stasel/WebRTC](https://github.com/stasel/WebRTC), pinned to 153.0.0 in both project.yml and Package.resolved. This adds binary size and a maintained dependency; Apple offers no public native RTCPeerConnection API. The standard voice engine remains independent. No WebView or remote HTML is involved.

The captured `NativeToolSession` calls authenticated, profile-scoped `/api/audio/voice-live/status` and `/api/audio/voice-live/session`. Hermes exchanges the SDP using its own OpenAI credential. The transport never requests or uses the provider key. The existing full configuration RPC used for voice preferences is transient and may contain server-configured secrets; only non-secret preferences are retained. Environment-based provider keys need not be returned by that RPC. SDP keeps its trailing CRLF. One audio track and `oai-events` data channel are negotiated before sending the offer. Commands wait for `session.started`; mute disables the local track and signals the vendor. Dismissal/background/route interruption invalidates callbacks and closes the peer immediately. There is no automatic reconnect or prompt retry.

`VoiceLiveProtocol` bounds startup history (24 messages / 6,000 characters), transcript context (five minutes / 512 fragments / 6,000 characters), duplicate delegation IDs and commentary chunks (480 UTF-8 bytes, within the 500-token append cap). `session.delegation.created` uses the last spoken user turn as the persisted prompt and recent speech as transient `voice_context`, with `surface: voice-live`. AppModel's existing prompt admission, ownership and uncertain-delivery logic is reused, without consuming the typed draft or attachments. Delegations are queued in order until Hermes is idle; one whose transcript is already present is submitted immediately, one that never receives a transcript is dropped with a notice. Hermes' answer is relayed to `session.commentary.append` as clauses arrive from `speechSink`, without awaiting a receipt per chunk; the queue drains at the end. Approvals and credential requests pause the relay without tearing the session down; the voice never approves them. Only real unavailability (status 404, missing key, configuration or session creation failure) switches the call to standard voice.

Opening voice honors the server profile's configured engine and voice. Choosing “GPT-Live · Stone · français” explicitly writes a minimal deep-merged voice configuration for that profile after checking server availability; it does not copy config or credentials between profiles. A session instruction requests French without replacing the server persona. Choosing standard voice is per-call and does not overwrite the server. All profiles are supported when that profile's server environment resolves an OpenAI key. Missing keys and older servers expose an actionable error and an explicit fallback.

The upstream endpoints were inspected at Hermes commit `7d7fe0043e` and re-audited at 0.21.7 (`71d34bad`); deployment must include these routes. Actual OpenAI latency, Stone voice quality, microphone echo cancellation and Bluetooth routing still require a keyed session on a physical iPhone.

## Local reading state and native controls

`ConversationActivity` stores reading markers and recent visits inside each saved gateway's cache, keyed by profile and stored session ID. The first complete history observation establishes a quiet discovery baseline; partial roster reads and search results do not initialize it. Older pages must not become unread merely because they are first loaded later. For known conversations, native message counts are authoritative: the roster's latest-message preview and the history's first-user-message preview have different meanings. Preview comparison is only a fallback when neither observation provides a count. Heartbeats, title edits and changing refresh timestamps do not by themselves mark a known conversation unread. These are local presentation markers, not cross-device read receipts.

Read state advances when the foreground chat is visible near its bottom, no tool sheet covers it, and its native transcript has been attached successfully. A failed or superseded attach does not mark a chat read. Archiving clears its local marker. Running and approval labels come from actual transcript state, rather than treating the selected conversation as inherently active.

Permissions remain schema-driven native settings. Common approval controls explain their effect and identify the profile they affect; detailed rules and structured preferences live in advanced settings. Changing their presentation does not alter server validation or authorization.

`RoutineSchedule` converts a small set of daily, weekday, weekly and hourly controls to native Hermes expressions. Custom expressions, intervals and one-shot schedules remain available in the advanced field. Editing a routine's text does not reschedule an unchanged one-shot. Hermes calculates execution times in its configured profile timezone; returned next-run timestamps are displayed in the iPhone's timezone. Run-result navigation uses a stored session ID returned by the native runs endpoint, never an ID inferred from the job or its destination. A timed-out trigger is treated as uncertain and is not automatically submitted again.

## Reconnect

The active chat resumes before roster/history refreshes, which run independently afterward. Callback ownership is scoped to the current socket and connection. Replay reads allow 40 seconds; an already obtained replay is reused when no second snapshot is needed.

1. Mint a new single-use ticket with the existing native session cookie (token-mode connections also mint one; `?token=` is only used by gateways without the ticket route).
2. Read `gateway.ready.payload.replay_epoch`, then declare `client.capabilities {server_requests: true}`: it is the handshake RPC and is required for approvals and questions to reach the app.
3. Reattach the stored conversation and receive its current runtime ID.
4. If epoch and runtime still match, fetch `session.events.since` after the last applied sequence.
5. Hold concurrent live events while that request runs, then merge by sequence and deduplicate before dispatch.
6. If the epoch changed, runtime changed, a send is uncertain, or the replay was truncated, fetch the native transcript/in-flight snapshot and rebase the visible tail.

Frames are received and decoded off the main actor (one `JSONSerialization` pass); a malformed envelope is skipped instead of closing the socket. Outgoing frames are encoded off the main actor and written strictly in call order. An `NWPathMonitor` reconnects at once when a usable network path appears or changes (a half-open socket is detected with a short ping instead of waiting for the heartbeat). Live events held during an attach are capped at 5,000; an overflow forces a snapshot recovery. `session.reclaimed` re-attaches the conversation.

Hermes' replay buffer is bounded. There is no atomic snapshot+cursor field in the inspected backend. The fallback can reconstruct a retained turn from `message.start`; otherwise it uses a linear-time overlap of the cumulative partial response and retained stream suffix. When the overlap cannot be proven, the existing partial response remains until `message.complete` provides the authoritative answer. The final native history is then reconciled without changing model context.

iOS suspends background execution. Temporary inactivity preserves the socket. When backgrounded, a finite UIKit background task lets an in-flight transmission finish and checkpoint its acknowledgement before disconnecting. This allowance can expire: an unconfirmed send is recovered from native history and is never automatically resent. Once accepted, the turn runs on the Hermes server; the app does not send an interrupt or session-close command when the phone locks. The inspected native orphan reaper preserves detached turns while their activity is fresh, then applies its own stale-work/cleanup policy. Returning to the app resumes the stored session and catches up via replay or native history. No background-audio mode or hosted relay is used. Optional APNs delivery requires a push-capable signing profile, an Apple push key and the included Hermes observer extension configured on the server; it is not activated by installing the app alone. See [notification setup](NOTIFICATIONS.md). The Mac and its agent must remain available; provider outages or a request for user approval can still delay completion.

## Sending and ambiguity

An optimistic user bubble appears on submit. The native acknowledgement confirms acceptance. Network loss after transmission leaves an **uncertain** bubble; an explicit RPC refusal marks it **failed**. A later authoritative snapshot can reconcile the optimistic row. Hermès iOS never automatically replays a plain chat submission, because JSON-RPC IDs alone do not provide durable idempotency.

Hosted groups are different: the native `groups.send` contract includes a durable event ID. Hermès iOS persists that ID before sending and reuses it for a user-requested retry. Group log cursors and event IDs deduplicate replay. Only the visible group polls its native log, at a two-second interval; no Hermès iOS group coordinator or bot relay exists.

## Privacy

Session cookies/tokens are stored in the Keychain with `AfterFirstUnlockThisDeviceOnly`. Passwords entered at login are cleared after authentication; credential-request values are transient. Cookie restore preserves the actual Secure flag (Foundation treats even a present `"FALSE"` string as secure).

Display caches live in Application Support, with data protection and backup exclusion. Each cached conversation is its own file (up to 500 messages), written only when it changes; the 30 most recently used are kept. The workspace file holds rosters, drafts and reading markers. A file that no longer decodes is moved aside instead of being overwritten, and cached models decode missing fields with defaults. Opening/recovery can retrieve native history. Connection removal erases its local files and Keychain entry. Hermès iOS has no analytics SDK, crash upload endpoint or advertising identifier.

ATS allows HTTP because tailnet IP addresses are user-configurable. Use `NSAllowsArbitraryLoads` alone: adding `NSAllowsLocalNetworking` makes iOS ignore that allowance, including for HTTP tailnet connections that ATS does not classify as local. See [Apple's documented precedence](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowsarbitraryloads).

Application URL validation restricts HTTP to loopback/private address ranges and private-network names; public addresses require HTTPS. Redirects are not followed, so login bodies and credentials are not forwarded to a new origin. HTTPS certificate validation remains the platform default. The separate socket session has a long resource timeout; short HTTP-request deadlines must not repeatedly tear down a healthy chat socket.

Attachments are stored as separate device-protected files, with per-connection/conversation draft metadata. Native `file.attach` stages bytes and returns the canonical file reference. Images are then queued using native `image.attach` with a percent-encoded file URL; this gives the app a known path to detach if the attach acknowledgment is lost. Cleanup paths are saved before queuing and resolved before any later text or voice turn. Uploads are staged only when Send is pressed. Photo-library images are downsampled with ImageIO to 3072 pixels and encoded as JPEG; image processing does not add another SDK dependency.

Conversation history uses date-grouped cards, previews and All/Unread/Archives filters. Search uses the native content-search endpoint while connected, with local title/preview matching as a fallback. Search and new-chat controls stay in the bottom row; a native X closes the sheet. Selecting the already attached conversation dismisses the sheet, preserving its draft and live turn; a previous attachment failure can be retried. The canonical Bot Chat from the native roster is included in ordinary history even though Hermes hides it from standard session lists. It is deduplicated by stored ID and does not affect the pagination offset or total for the ordinary list. History loads from the current cache before refreshing; errors leave cached rows visible. Concurrent native `session.list` reads share one request per socket/profile. The sheet waits for a connected socket and refreshes automatically after reconnection. Any successful refresh clears an earlier error, while failures expose the underlying RPC reason. A listing failure does not close an otherwise healthy chat connection. Heartbeat replies allow 45 seconds to tolerate observed server event-loop stalls; actual transport failures still trigger immediate recovery.

History cards keep title and preview on one line at standard text sizes, with trailing truncation and a compact 68-point minimum height. Accessibility text sizes allow the title and preview to wrap. Status labels distinguish an actual running turn, a request for the user's input and unread activity.

Conversation lists are persisted per profile with backward-compatible migration from the former single list. Profile switching renders that profile’s cached list immediately and revalidates separately. A slow background response can update its own cached profile without replacing the currently displayed list. The connection indicator remains distinct from the activity label; after 15 seconds without progress during thinking, the label reports that the model response is pending, without claiming a provider outage.

## Streaming and chat rendering

Native `message.delta` remains the only source of streamed reply text. The first nonempty fragment bypasses batching; subsequent fragments are coalesced at approximately 30 fps. Empty fragments retain the thinking indicator, and interrupted/error turns finalize their partial bubble so a later reply cannot append into it. Earlier unchanged message views and Markdown blocks use value equality to avoid unnecessary rerendering. Only `ChatTranscriptView` reads the transcript; the header and composer receive plain values and skip unchanged updates. Finished messages keep their Markdown parse in a bounded cache; while streaming, only the tail after the last stable block boundary is re-parsed, and code blocks are measured in 40-line chunks.

Tool calls are presented as a collapsed activity summary with an optional list of running, completed or stopped steps. `Transcript` keeps at most 40 steps identified by native tool IDs, resets them at the next turn, and can rebuild them from retained replay events. Steps are not persisted in `ChatSnapshot` and do not carry over when switching conversations. This is a lightweight activity view, not a complete execution log or a renderer for tool outputs.

The chat uses a small Foundation block parser plus Apple's inline `AttributedString` Markdown interpretation. Supported blocks are ATX headings, paragraphs, ordered/unordered/task list items with indentation, block quotes, pipe tables, horizontal rules and backtick/tilde fences. Streaming can end in an unfinished code fence. Code keeps indentation and provides a 44-point copy action; wide code and tables scroll horizontally. Raw HTML, remote image loading, LaTeX and full CommonMark/GFM conformance are not implemented. No WebView, syntax-highlighting engine or runtime package is added. Unsupported constructs remain readable text. User messages are rendered verbatim, so underscores and code punctuation are preserved.

Sending dismisses the keyboard and follows the reply. Content growth cannot independently disable following; an upward reading gesture pauses it, and the latest-message button restores it. The redundant conversation banner has been removed.

## No Liquid Glass

iOS 26+ draws glass behind bar buttons, the back button, `.searchable`, `Menu`, menu `Picker`, segmented controls, switches, action sheets and alerts, and iOS 27 ignores `UIDesignRequiresCompatibility`. `Features/AppChrome.swift` therefore replaces each with an opaque, `AppTheme` control: `AppToolbarItem` (hidden shared background), `appNavigationBar()` (plain chevron back button plus swipe-back, applied by `modernList()`), `AppSearchField`/`AppSearchSection`, `AppMenu`/`AppMenuButton`/`AppPicker`/`appContextMenu` (opaque popovers), `AppSegmented`, `AppToggleStyle`, and `appAlert`/`appConfirm` (compact bottom card). Global notices use `NoticeDialog`, an in-app overlay that works while a sheet is open. Do not reintroduce the system versions. Message sharing still opens the system share sheet.
